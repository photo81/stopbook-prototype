# 어드민 회원 기능 검토 — 2026-10-26

검토 기준은 프로젝트 폴더의 엑셀 기능명세입니다. **자동 탈퇴, 수신 동의 변경, 단체 신청 저장의 오류를 먼저 수정해야 하며, 회원통합·배송지 관리·회원별 이력 조회를 추가해야 합니다.** 화면과 기능 코드는 변경하지 않았습니다.

**검토 기준과 범위**

- 기준 파일: `ing ■ (포토) 스탑북 리뉴얼 프로젝트_유저_관리자IA ver0.02(초안) (2).xlsx`
- 주 기준 시트: `ing_To-be_관리자_IA(ver0.02)`, 최종수정일 2026-10-22(E2). 회원관리 18~35행, 회원 분석 관련 119~123행을 대조했습니다.
- 연동 확인 시트: `To-be_유저화면목록(ver0.03)`, 최종수정일 2026-10-21(D2).
- 검토 대상: 통합 회원 목록·상세, 단체 신청·승인·만료, 탈퇴, 회원구분·등급·혜택 설정 및 사용자 정보수정·로그인·메시지 연동.
- 엑셀의 화면 ID 열은 비어 있습니다. 아래 근거는 시트명·행·셀로 표시하며, 로컬 HTML 명세의 `PRD_MEM_*`를 엑셀의 요구사항 ID로 간주하지 않았습니다.
- 실제 JS 소스를 V8에서 실행하고 메모리 저장소·테스트 시계로 저장/재로드 결과를 검증했습니다. 브라우저 전체 화면 조작, 실제 본인인증·메시지 발송·서버 API는 검증하지 않았습니다. 실행 검증은 실제 브라우저 저장소를 변경하지 않았습니다.
- 현재 프로젝트는 샘플 데이터와 localStorage를 사용하는 프로토타입입니다. API·OAuth·발송 연동 TODO는 별도 구현 과제로 분류하고, 현재 구현 안에서 재현되는 오류와 구분했습니다.

**R01. 안내 당일 로그인한 회원이 자동 탈퇴됨**

- 근거: [member-data.js:1350](../admin/member-data.js#L1350)의 안내 취소 조건, [1362행](../admin/member-data.js#L1362)의 탈퇴 예정일 판정. 로그인 기록은 [814행](../admin/member-data.js#L814)에서 날짜만 저장합니다.
- 재현: 테스트 시계 2026-10-26에 No.1001의 장기미이용 안내 생성 → 같은 날 `Auth.recordLogin` → 2026-11-25에 `runDormantBatch` 실행.
- 결과: 미접속 365일 기준인데도 최근 로그인 후 30일 만에 `withdrawn=true`가 됩니다. 안내일과 로그인일이 같으면 날짜의 `>` 비교가 성립하지 않고, 예정일에 미접속 일수를 다시 검사하지 않기 때문입니다.
- 수정: 로그인 시각 또는 로그인 이벤트로 안내를 취소하고, 탈퇴 직전에 최근 로그인·미접속 일수·적용 중인 탈퇴정책을 재검증해야 합니다.

**R02. 회원의 최신 수신 거부가 이전 관리자 값에 덮임**

- 근거: [member-data.js:918](../admin/member-data.js#L918)에서 회원 수정값을 반영한 뒤, [1288행](../admin/member-data.js#L1288)과 [1305행](../admin/member-data.js#L1305)에서 관리자 수정값을 다시 적용합니다.
- 재현: 관리자에서 No.1001 SMS=동의·성별=남 저장 → 회원이 SMS=거부·성별=여 저장 → 동일 저장소로 모듈 재로드.
- 결과: 저장 직후 SMS=N·성별=여 → 재로드 후 SMS=Y·성별=남. 개인정보 이용 동의는 N인데 SMS 수신은 Y인 모순 상태도 재현됩니다.
- 수정: 관리자·회원 변경을 같은 회원 원장에 저장하거나, 필드별 최종 변경 시각으로 병합해야 합니다. 관리자 저장도 변경한 필드만 보내도록 보완해야 합니다.

**R03. 여러 창에서 단체 신청 처리 결과가 유실됨**

- 근거: [member-data.js:604](../admin/member-data.js#L604)의 `saveApplication`은 최초 로드한 `appOverlay` 전체를 다시 저장합니다.
- 재현: 창 A와 B를 모두 먼저 열기 → A에서 501번 반려 → B에서 502번 반려 → 재로드.
- 결과: 501번은 대기, 502번만 반려로 남습니다. 다른 신청 건을 처리해도 기존 결과가 사라집니다.
- 수정: 저장 직전에 최신 저장값을 읽어 해당 신청만 병합해야 합니다. 동일 신청의 동시 수정은 버전 확인 또는 충돌 안내가 필요합니다.

**5. 권장 작업 순서와 검수 기준**

1. **회원 데이터 정합성부터 수정:** R01~R04. 같은 날 재로그인, 관리자/회원 순차 변경, 두 창 처리, 승인 후 재로드에서 최신 상태가 유지되어야 합니다.
2. **등급·혜택 정확성 수정:** R05~R09 및 등급 고정 정책. 월말·2월·지연 실행, 신규 등급, 저장 실패에서 기간·잔액·집계·출력이 일치해야 합니다.
3. **명세의 명확한 누락 기능 추가:** 회원통합, 배송지 목록, 회원별 로그인·메시지·리뷰/이벤트 이력을 순차 구현합니다.
4. **정의가 필요한 용어 확정:** 마스터회원, 평생회원, 이용권, 관리메시지, 운영설정 범위. 엑셀 자체의 질문과 공란을 기능 결함으로 단정하지 않습니다.
5. **실서비스 연동 검수:** 인증·권한·실제 발송·지급 배치·감사기록을 연결한 뒤 브라우저 통합 검증을 진행합니다.
