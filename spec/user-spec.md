# 스탑북 사용자(쇼핑몰 고객) 화면 기능 명세

- 문서 성격: 사용자 화면 프로토타입(`user/`)의 **화면 작동·상세 기능 정의서**. 코드를 기준으로 작성했고, 입력 규칙·검증 메시지·동작 흐름·저장 키를 실제 값 그대로 적음
- 작성 기준일: 2026-10-26
- 기준 문서: `IA기획.xlsx` — `To-be_유저화면목록(ver0.03)`, `To-be_유저_IA(ver0.02)`, `공통 컴포넌트`, `공통 규칙`
- 함께 보는 문서: `spec/admin-spec.md` (관리자 기능 명세 — 회원 데이터·탈퇴·서류 등 관리자 쪽 처리), `spec/members-signup-spec.html` (회원·가입 영역 화면 정의서, HTML)
- **유지 규칙: 기능을 수정하거나 추가하면 이 문서의 해당 절을 같은 작업에서 함께 갱신한다.** 화면 문구·검증 메시지·저장 키가 바뀌면 본문과 §17 공유 데이터 표를 모두 맞춘다
- 구현 범위: 회원 영역(로그인/회원가입/정보 찾기/비밀번호 찾기)과 마이페이지(요약·주문/배송·회원정보 수정·회원 탈퇴). 주문서·장바구니 등은 미구현(placeholder) — §19 참고. 고객센터(FAQ·1:1 문의·제휴문의)는 §20~22, 마이페이지 주문/배송은 §23
- 실행: `user/signup.html`(회원가입·로그인), `user/mypage.html`(마이페이지). 카카오 우편번호 검색은 `file://`에서 동작하지 않으므로 `프로토타입 실행.bat`(http://localhost:8090) 또는 GitHub Pages(https://photo81.github.io/stopbook-prototype/)에서 확인

## 1. 쇼핑몰 공통 (상단 유틸 메뉴 · 로그인 상태 · 토스트)

### 1.1 화면 구성
- 경로: `user/signup.html`(회원가입/로그인), `user/mypage.html`(마이페이지), `user/support.html`(고객센터), `user/cart.html`(장바구니, §25). 네 화면 모두 상단에 `PROTOTYPE - …` 띠와 유틸 메뉴(오른쪽 정렬, 최대 폭 1136px).
- 유틸 메뉴 순서: [로그인/회원가입] · [마이페이지] · [장바구니 (0)] · [고객센터]. [마이페이지]→`mypage.html`, [고객센터]→`support.html`; 현재 화면은 `aria-current="page"`.
- 로그인 후: [로그인/회원가입] 자리가 `{이름}님 [로그아웃]`으로 바뀜. support.html의 [로그인/회원가입]은 `signup.html#login`으로 이동하고 `sessionStorage['stopbook.afterLogin']='support.html'`로 로그인 후 돌아옴.
- [장바구니 (n)] → `user/cart.html`(§25). n = 로그인 회원의 장바구니 종 수(`m.cart.length`, `#utilCart`), 비로그인 0. (2026-10-27 — 이전에는 "준비 중" 토스트)
- signup.html 본문: 프로토타입 안내 문단만(샘플 계정·테스트 인증번호·저장 위치 안내). 쇼핑몰 메인은 `index.html`(§24).

### 1.2 로그인 상태(세션)
- `sessionStorage['stopbook.session']` = 로그인한 회원 번호(`no`). 새로고침해도 유지, 탭을 닫으면 로그아웃. 복원 시 `MemberData.members`에서 `no`가 같고 `withdrawn`이 아닌 회원만 복원(탈퇴 회원이면 키 삭제).
- 로그아웃: 키 삭제 → 메뉴 복원 → 토스트 `로그아웃되었습니다.` (mypage는 추가로 "로그인이 필요합니다" 카드 표시).
- 접속 기기: UA에 `Mobi|Android|iPhone|iPad`가 있으면 `MO`, 아니면 `PC` → 로그인 시 `MemberData.Auth.recordLogin(no, env)`로 최근접속일·접속 기기 저장(관리자 회원 목록 "최근접속일", 상세 "접속 기기").
- 토스트: 화면 하단 중앙 2.4초. `<dialog>`가 열려 있으면 가장 위 dialog 안으로 옮겨 모달 위에 표시.

### 1.3 모바일·접근성 공통
- 모달(`.auth`): 폭 `min(480px, 100vw-32px)`, 560px 이하에서는 전체 화면(100dvh, 모서리 0). 모달이 열리면 `body` 스크롤 잠금.
- 480px 이하: 유틸 메뉴 간격 16px, 입력 폼의 항목명을 입력칸 위로(1열).
- 입력 오류: 칸 아래 `.msg.err` 빨간 문구(`aria-live="polite"`) + 빨간 테두리 + `aria-invalid="true"`. 폼 제출 시 첫 오류 칸으로 포커스.
- 로그인 오류 박스 `role="alert"`, 단계 표시 `aria-current="step"`, 성별 `role="radiogroup"`, 비밀번호 [보기/숨기기] `aria-pressed`.
- 모달을 열면 포커스를 로고(`tabindex=-1`)에 두어 닫기 버튼에 포커스 링이 생기지 않게 함.

## 2. 로그인/회원가입 모달 첫 화면 (IA: 로그인)

### 2.1 경로/진입
- `signup.html` 상단 [로그인/회원가입] 클릭, 또는 해시 `#join`.
- 해시 라우팅(페이지 로드 시 1회 판정 후 `history.replaceState`로 해시 제거 → 새로고침해도 모달이 다시 뜨지 않음):

| 해시 | 동작 |
|---|---|
| `#join` | 첫 화면 모달 열기 |
| `#signup` | 모달 열기 + 스탑북 회원 가입 1단계(정보 입력)로 바로 |
| `#login` | 스탑북 회원 로그인 화면으로 바로 |
| `#find-id` / `#find-pw` | 내 로그인 정보 찾기 / 비밀번호 찾기로 바로 |

### 2.2 화면 구성
- 로고(`images/logo-stopbook.png`, 132px) · [스탑북 회원 로그인](주 버튼) · [스탑북 회원 가입](선 버튼) · 구분선 · SNS 원형 아이콘 3개(카카오 #FEE500 · 네이버 #03C75A · 구글 흰 바탕 4색 G) · 하단 링크 "내 로그인 정보 찾기".
- 비밀번호 찾기 링크는 첫 화면에 없고 로그인 화면 하단에만 있음(스탑북 회원만 해당).
- 헤더: 왼쪽 [‹ 이전](login·find·sns·terms·info 화면에서만 표시) · 가운데 제목 · 오른쪽 [× 닫기].
- 헤더 제목: 가입 단계 = 가입 방법(`스탑북 회원 가입` / `카카오로 가입` / `네이버로 가입` / `구글로 가입`), login = `스탑북 회원 로그인`, pw = `비밀번호 변경`, find = `내 로그인 정보 찾기` 또는 `비밀번호 찾기`, 그 외 빈 제목.

### 2.3 화면 이동(모달 내부 상태 `state.view`)

| 현재 | 다음 | [‹ 이전] |
|---|---|---|
| start | login / info(스탑북 가입) / sns / find | 없음 |
| login | 완료 / pw(비밀번호 변경) / find / info / sns | start |
| sns | 기존 회원: 완료 / 신규: info | 들어온 화면(start 또는 login) |
| info(1단계) | terms | SNS 가입이면 sns, 아니면 들어온 화면 |
| terms(2단계) | done | info |
| done(3단계) | 모달 닫기 | 없음 |
| find | 결과 | 들어온 화면(start 또는 login) |
| pw | 완료 | 없음 |

### 2.4 입력 보호(가입 단계 info·terms)
- 더티 판정: 휴대폰 인증 완료 또는 이름·휴대폰·이메일·생년월일·비밀번호·닉네임 중 하나라도 입력.
- Esc(`cancel` 이벤트)·[×]·브라우저/모바일 뒤로가기 시 확인 창: `회원가입을 그만두시겠습니까?\n입력한 정보와 휴대폰 인증이 모두 사라집니다.` 취소하면 모달 유지.
- 뒤로가기: 가입 단계 진입 시 `history.pushState({signupGuard:1})`를 1개 쌓음. `popstate`에서 terms이면 info로 한 단계 뒤로(다시 쌓음), info이면 확인 후 닫기. 모달이 닫힐 때 쌓아 둔 기록은 `history.back()`으로 정리. `file://` 등 pushState 불가 환경은 무시.
- 모달이 닫히면 인증 타이머 정지, `sessionStorage['stopbook.afterLogin']` 삭제(로그인하지 않고 닫으면 마이페이지 복귀 취소).

### 3.3 동작 흐름
1. 아이디·비밀번호 둘 중 하나라도 비면 `아이디와 비밀번호를 입력해 주세요.` (값은 검증하지 않음).
2. SNS가 넘겨주는 이메일 결정: 입력값에 `@`가 있으면 그대로 / 숫자만 10자리 이상(전화번호)이면 가상 프로필 이메일 / 그 외 `{입력}@{도메인}`.
3. `MemberData.findSnsMember(code, email, 가입유형명)`: 가입 때 저장한 `snsKey`(`{code}:{email 소문자}`)가 같은 회원 → 없으면 `snsKey`가 없는 예전 회원 중 같은 가입유형·같은 이메일. 탈퇴 회원 제외.
   - 있으면 `Auth.recordLogin` → 모달 닫기 → 토스트 `{이름}님, {SNS} 계정으로 로그인되었습니다.`
4. 없으면 `findDuplicate({email})`로 다른 방법으로 가입된 이메일인지 확인(SNS 로그인으로 이메일 주인이 확인됐으므로 가입 방법을 알려 줌):
   - 다른 SNS: `이 이메일은 {SNS} 계정으로 가입되어 있습니다.` + [{SNS}로 로그인](해당 SNS 화면으로)
   - 스탑북 회원: `이 이메일은 스탑북 회원(이메일 로그인)으로 가입되어 있습니다.` + [이메일로 로그인](이메일 채워 로그인 화면) [비밀번호 찾기](이메일 채워 찾기)
5. 둘 다 아니면 신규: 토스트 `{SNS} 로그인 완료 · 처음 오셨네요! 스탑북 가입을 진행합니다.` → 가입 1단계로(이름·이메일 미리 채움, 비밀번호 칸 숨김, 생년월일 선택).

### 3.4 마이페이지 로그인 모달의 SNS 화면 차이(§12)
- 이메일 결정이 단순함(`@` 없으면 `{입력}@{도메인}`). 신규 회원이면 가입을 진행하지 않고 `{SNS} 계정으로 가입한 회원 정보가 없습니다.` + `회원가입 후 이용해 주세요.`(링크 `signup.html#signup`).

## 4. 스탑북 회원 로그인 (PRD_MEM_001)

### 4.1 경로/진입
- 첫 화면 [스탑북 회원 로그인], 해시 `#login`, 각종 [로그인] 버튼(`data-login="{이메일}"`이면 이메일을 미리 채움).

### 4.2 화면 구성
- 입력: `이메일 또는 아이디`(autocomplete username) · `비밀번호` + [보기/숨기기] 토글 · 체크 `이메일(아이디) 저장` · 오류 박스 · [로그인].
- 하단 링크: 내 로그인 정보 찾기 | 비밀번호 찾기 | 회원가입. 구분선 아래 SNS 아이콘 3개(첫 화면과 동일 마크업 복제).
- 열 때: `localStorage['stopbook.savedLoginId']`가 있으면 아이디 채움 + 저장 체크. 아이디가 있으면 비밀번호 칸에, 없으면 아이디 칸에 포커스.

### 4.3 검증·메시지

| 상황 | 문구(오류 박스) |
|---|---|
| 아이디 비움 | `이메일 또는 아이디를 입력해 주세요.` |
| 비밀번호 비움 | `비밀번호를 입력해 주세요.` |
| 잠금 중 | `비밀번호를 5회 잘못 입력해 **HH:mm**까지 로그인이 제한됩니다.` + 보조 `비밀번호가 기억나지 않으면 비밀번호 찾기에서 새 비밀번호를 설정해 주세요.` |
| 불일치(없는 계정·SNS 계정·비밀번호 오류 모두 동일) | `이메일(아이디) 또는 비밀번호가 맞지 않습니다.` + 보조 `비밀번호를 5회 연속 잘못 입력하면 10분간 로그인이 제한됩니다. 카카오·네이버·구글로 가입하셨다면 아래 간편 로그인을 이용해 주세요.` |

- 로그인 화면에서는 **틀린 횟수를 표시하지 않음**(횟수는 존재하는 계정에만 생기므로 가입 여부가 드러남). 횟수 표시는 마이페이지 비밀번호 확인(§14)에서만.
- 잠금 시각은 `until`(YYYY-MM-DD HH:mm)의 시각 부분(`slice(11)`)만 표시.

### 4.4 동작 흐름
1. `MemberData.Auth.login(id, pw, env)` 호출(§17.1).
2. 성공 시 저장 체크면 `stopbook.savedLoginId`에 입력값 저장, 아니면 삭제.
3. `res.change`가 `temp`(임시 비밀번호) 또는 `expired`(90일 경과)이면 비밀번호 변경 화면(§5)으로.
4. 아니면 완료: 상단 `{이름}님 [로그아웃]`, 세션 저장, 모달 닫기, 토스트 `{이름}님, 반갑습니다.`
5. `sessionStorage['stopbook.afterLogin']`이 `xxx.html` 형식이면 0.6초 뒤 그 화면으로 이동(마이페이지에서 넘어온 경우).

## 5. 비밀번호 변경 유도 (임시 비밀번호 · 90일, PRD_MEM_006)

### 5.1 진입
- 로그인 성공 직후 `change === 'temp'`(관리자가 패스워드 초기화로 임시 비밀번호 발급) 또는 `change === 'expired'`(변경일로부터 90일 이상, 다음 안내일(`snoozeUntil`)이 지난 경우). signup.html·mypage.html 로그인 모달 모두 동일.

### 5.2 화면 구성

| 종류 | 제목 | 설명 | [다음에 변경하기] |
|---|---|---|---|
| temp | 새 비밀번호를 설정해 주세요 | 임시 비밀번호로 로그인하셨습니다. 안전을 위해 새 비밀번호로 변경한 뒤 이용해 주세요. | 숨김(변경 필수) |
| expired | 비밀번호를 변경해 주세요 | 비밀번호를 변경한 지 90일이 지났습니다 (최근 변경 YYYY-MM-DD). 개인정보 보호를 위해 비밀번호를 변경해 주세요. | `다음에 변경하기 (30일 뒤 다시 안내)` |

- 입력: 새 비밀번호 · 새 비밀번호 확인 · [비밀번호 변경]. 헤더에 [이전] 없음(닫기는 가능하며 이때 로그인되지 않음).

### 5.3 검증(순서대로, 첫 오류만 표시)

| 순서 | 문구 |
|---|---|
| 비움 | `비밀번호를 입력해 주세요.` |
| 공백 포함 | `비밀번호에 공백을 넣을 수 없습니다.` |
| `^(?=.*[A-Za-z])(?=.*\d)(?=.*[^A-Za-z\d\s]).{8,20}$` 불일치 | `8~20자, 영문·숫자·특수문자를 모두 포함해 주세요.` |
| 이메일 앞부분(4자 이상)을 포함 | `비밀번호에 아이디(이메일 앞부분)를 포함할 수 없습니다.` |
| 아이디(이메일이 아닌 기존 아이디)를 포함 | `비밀번호에 아이디를 포함할 수 없습니다.` |
| 현재 비밀번호와 같음(`Auth.isSamePassword`) | temp: `임시 비밀번호와 다른 비밀번호를 입력해 주세요.` / expired: `현재 비밀번호와 다른 비밀번호를 입력해 주세요.` |
| 확인 비움 / 불일치 | `새 비밀번호를 한 번 더 입력해 주세요.` / `비밀번호가 일치하지 않습니다.` |

### 5.4 동작·저장
- 변경: `Auth.setPassword(no, pw, { by: '회원', content: '패스워드 변경 (회원)' })` → 완료 처리 + 토스트 `비밀번호가 변경되었습니다. 로그인되었습니다.` 관리자 회원 상세 히스토리에 `패스워드 변경 (회원)`(담당자 회원), 패스워드 "최근 변경" 갱신, 임시 표시 해제.
- 다음에 변경: `Auth.snoozePassword(no)` → `snoozeUntil` = 오늘+30일, 히스토리 `패스워드 변경 안내: 다음에 변경 (YYYY-MM-DD에 다시 안내)` → 그대로 로그인 완료.
- IA 대비 메모: IA는 [비밀번호 변경하기]→회원정보수정 랜딩 / [3개월 후 변경하기]. 프로토타입은 모달 안 즉시 변경 / 30일 뒤 재안내.

| 비밀번호 확인(blur) | 일치 | `비밀번호를 한 번 더 입력해 주세요.` / `비밀번호가 일치하지 않습니다.` | `비밀번호가 일치합니다.` |

### 6.4 휴대폰 인증 흐름
1. [인증번호 받기]: 번호 형식 검사 → 6자리 난수 생성, 만료 = 현재+180초, 시도 0 → 인증번호 칸·`테스트 인증번호: 123456` 표시, 버튼 `다시 받기`, 타이머 `m:ss` 1초 갱신.
2. [확인]: 불일치면 시도 +1(5회에 코드 무효) / 일치면 타이머 정지 → `findDuplicate({phone})` → 있으면 중복 박스 / `rejoinBlock` → 제한 안내 / 통과면 `state.phoneVerified` = 숫자만, 버튼 `인증 완료`(비활성).
3. 인증 후 번호를 고치면 인증 해제·중복 박스 닫기, 버튼 `인증번호 받기`로 복귀.

### 6.5 [다음]
- 이름·생년월일·비밀번호·확인·닉네임 검사 + 휴대폰 인증 여부 + 이메일 중복 확인 여부(확인한 이메일과 현재 값이 같아야 함). 하나라도 실패하면 첫 `.invalid` 칸(없으면 휴대폰)으로 포커스. 통과하면 2단계 약관 동의.

## 7. 회원가입 2단계 — 약관 동의

### 7.1 화면 구성

| key | 라벨 | 구분 | [보기] |
|---|---|---|---|
| tos | 서비스 이용약관 동의 | [필수] | 있음(샘플 4개 조항) |
| privacy | 개인정보 수집·이용 동의 | [필수] | 있음(수집 항목: 스탑북 `이메일(로그인 아이디), 비밀번호, 이름, 생년월일, 휴대폰 번호` / SNS `{SNS} 계정 식별값, 이름, 이메일, 휴대폰 번호 (생년월일은 입력한 경우)`) |
| age14 | 만 14세 이상입니다 | [필수] | 없음 |
| marketingUse | 마케팅 목적 개인정보 수집·이용 동의 | [선택] | 있음 |
| ad | 광고성 정보 수신 동의 | [선택] | 있음. 하위 채널 체크 `SMS` · `이메일` + 안내 `광고성 정보 수신은 마케팅 목적 개인정보 수집·이용 동의와 함께 선택됩니다.` |

- 약관 레이어(`#termsDlg`, 모달 위 한 겹): 제목·본문(맨 위 `샘플 문구입니다. 실제 약관은 법무 검토 후 확정해 주세요.`)·[동의하기](해당 항목 체크 후 닫기)·[×]/바깥 클릭 닫기.

### 7.2 연동 규칙
- `ad` 체크 → SMS·이메일 모두 체크 + `marketingUse` 자동 체크. 채널 하나만 체크면 `ad`는 indeterminate(일부 선택).
- 채널 체크 → `marketingUse` 자동 체크. `marketingUse` 해제 → 채널 모두 해제(마케팅 활용 동의 없이 광고 수신만 받지 않음).
- [전체 동의] = 모든 체크 상태와 동기화(일부만 체크 시 indeterminate).
- [가입하기] 활성 조건: tos·privacy·age14 모두 체크.

### 7.3 [가입하기] 처리(submit)
1. 동의 내역 `consents = { at, items: [{key,label,required,agreed}] }` 생성(광고 채널은 `광고성 정보 수신 동의 (SMS)`처럼 라벨링, 마케팅 미동의면 채널은 모두 N).
2. 가입 혜택: `MileageTypes.list()` 중 조건 `회원가입 완료` · 상태 `적용 중` · 대상 `신규 가입 회원`/`전체 회원` · 방식 `fixed`인 유형마다 적립(기본 `회원가입 적립` 2,000P, 처리자 시스템) + `신규가입 10% 할인` 쿠폰 1장(`MemberData.COUPONS` 고정 목록).
3. 히스토리: `약관 동의: 서비스 이용약관·개인정보 수집·이용·만 14세 이상(필수), 마케팅 목적 개인정보 수집·이용, 광고성 정보 수신(SMS·이메일)`(동의한 것만) · `마일리지 지급: 2,000P (사유: 회원가입 적립)` · `쿠폰 발급: 신규가입 10% 할인`.
4. `MemberData.registerMember({...})`: memberType = 회원 유형 관리의 가입유형 이름(기본 스탑북회원/카카오회원/네이버회원/구글회원), snsKey(SNS 가입만), userId = 이메일, name·email·phone(하이픈)·birth·nickname·gender·marketingUse/Sms/Email·consents·joinEnv(PC/MO)·ledger·history.
   - 오류(`이미 가입된 휴대폰 번호입니다.` / `이미 사용 중인 이메일입니다.` / `탈퇴 후 재가입 제한 기간입니다. YYYY-MM-DD부터 다시 가입할 수 있습니다.` / `가입 정보를 저장하지 못했습니다. 잠시 후 다시 시도해 주세요.`)면 1단계로 돌아가 폼 오류 박스에 표시.
5. 스탑북 가입이면 `Auth.setPassword(no, pw, { log:false })`로 비밀번호 저장(히스토리 없음).
6. 가입 환영 메일 기록: `MessageStore` 템플릿 `email_welcome`(`[스탑북] #{이름}님, 가입을 환영합니다`)을 채워 이메일 발송 내역에 1건 추가(처리자 시스템) → 관리자 > 메시지 > 이메일 발송 내역.
7. 3단계 렌더 → `signedIn(member)`(즉시 로그인 상태) → `stopbook.afterLogin`이 `mypage.html`이면 완료 버튼 문구 `마이페이지로 돌아가기`, 아니면 `스탑북 시작하기`.

## 10. 비밀번호 찾기 (PRD_MEM_005, 휴대폰 인증 후 즉시 재설정)

### 10.1 경로/진입
- 로그인 화면 "비밀번호 찾기", 찾기 결과·SNS 화면의 [비밀번호 찾기](`data-email`로 이메일 채움), 해시 `#find-pw`, 마이페이지 비밀번호 확인 하단 링크 `signup.html#find-pw`. 로그인 화면에서 들어오면 아이디 칸 값을 그대로 채움(아이디도 허용).

### 10.2 화면 구성
- 설명 `가입한 이름, 이메일(또는 아이디), 휴대폰 번호를 입력하고 휴대폰 인증을 해 주세요. 본인 확인이 끝나면 새 비밀번호를 바로 설정할 수 있습니다.`
- 입력: 이름 · `이메일·아이디`(text, `가입한 이메일 또는 아이디`) · 휴대폰 + 인증 · (본인 확인 후 표시) 새 비밀번호 · 새 비밀번호 확인 · [비밀번호 재설정하기](비활성 시작).

### 10.3 동작 흐름
1. [인증번호 받기] 전에 이름·이메일(아이디) 입력 검사(`이름을 입력해 주세요.` / `이메일 또는 아이디를 입력해 주세요.`) — 인증 직후 가입 여부를 확인하므로 먼저 받음.
2. 인증 성공 즉시 계정 확인(이름 + 이메일 또는 아이디 + 인증 번호):
   - 없음 → 바로 "찾지 못함" 결과(§9.4와 동일 화면, [다시 입력]은 비밀번호 찾기 모드).
   - SNS 계정 → 결과 `{SNS} 간편 로그인 계정입니다` · `간편 로그인 계정은 비밀번호가 없습니다. {SNS}로 로그인해 주세요.` + 요약 + [{SNS}로 로그인].
   - 스탑북 회원 → `본인 확인이 완료되었습니다. 아래에 새 비밀번호를 입력해 주세요.`(ok) + 새 비밀번호 칸 표시·버튼 활성, 포커스 이동.
3. 확인 뒤 이름·이메일·휴대폰을 고치면 확인 상태 해제(인증부터 다시).
4. [비밀번호 재설정하기]: 규칙 §5.3(아이디 포함 금지 포함) + 같은 비밀번호면 `이전 비밀번호와 다른 비밀번호를 입력해 주세요.` → `Auth.setPassword(no, pw, { by:'회원', content:'비밀번호 재설정 (비밀번호 찾기 · 휴대폰 인증)' })`.
5. 안내 문자 기록: `MessageStore.addLog({ channel:'sms', templateName:'비밀번호 재설정 안내', by:'시스템', sample:'[스탑북] {이름}님의 비밀번호가 재설정되었습니다. 본인이 아니라면 고객센터(080-860-1119)로 알려 주세요.' })` → 관리자 > 메시지 > SMS 발송 내역.
6. 결과: `비밀번호가 재설정되었습니다` · `새 비밀번호로 로그인해 주세요. 010-****-1234(으)로 재설정 안내 문자를 보냈습니다.` · [로그인하기](이메일 채움).
- 관리자 반영: 회원 상세 패스워드 "최근 변경" 갱신, 잠금·임시 상태 해제, 히스토리 `비밀번호 재설정 (비밀번호 찾기 · 휴대폰 인증)`(담당자 회원).
- TODO: 실서비스는 인증 토큰으로 재설정 요청 검증, 안내 수단(SMS/알림톡) 확정. 임시 비밀번호는 관리자 패스워드 초기화에서만 발급.

## 11. 마이페이지 진입·라우팅 (`user/mypage.html`)

### 11.1 주소
| 주소 | 화면 |

### 11.2 레이아웃(고정 상단·서브 탭)

1. [인증번호 받기] → 가입한 번호로 가상 발송: `010-****-1234(으)로 인증번호를 보냈습니다. 3분 안에 입력해 주세요.` 인증 규칙·오류 문구는 §6.3 인증번호와 동일.
2. 성공: 토스트 `본인 인증이 완료되었습니다.` + 박스 `✓ 본인 인증이 완료되었습니다. 이메일·휴대폰 번호를 변경할 수 있습니다.` → 이메일(+[중복 확인])·휴대폰(+[인증번호 받기]) 입력칸 표시.
3. 이메일 안내(계정별): SNS 회원은 읽기 전용 `{SNS} 간편 로그인 계정의 이메일은 {SNS}에서 받은 정보라 변경할 수 없습니다.` / 이메일 로그인 계정 `이메일로 로그인하는 계정입니다. 이메일을 바꾸면 로그인 아이디도 새 이메일로 바뀝니다.` / 아이디 계정 `로그인 아이디({아이디})는 바뀌지 않습니다.`
4. 이메일 [중복 확인]: `이메일 주소를 정확히 입력해 주세요.` / 같은 값 `현재 사용 중인 이메일입니다.`(info) / `findDuplicate({email}, 본인 제외)` 중복 `이미 사용 중인 이메일입니다. 다른 이메일을 입력해 주세요.` / `사용할 수 있는 이메일입니다.`(ok). 수정 시 `이메일이 바뀌어 다시 중복 확인이 필요합니다.`(info). 저장 시 미확인 `이메일 중복 확인을 해 주세요.`
5. 휴대폰 [인증번호 받기] 전 검사: `휴대폰 번호를 정확히 입력해 주세요.` / 같은 번호 `현재 등록된 번호입니다. 바꿀 번호를 입력해 주세요.`(info). 새 번호로 인증 성공 후 `findDuplicate({phone}, 본인 제외)` → 중복 `이미 다른 계정에 등록된 휴대폰 번호입니다. 고객센터(080-860-1119)로 문의해 주세요.` / 통과 `새 휴대폰 번호 인증이 완료되었습니다.`(버튼 `인증 완료`). 번호 수정 시 `휴대폰 번호가 바뀌어 다시 인증해야 합니다.` 저장 시 미인증 `새 휴대폰 번호 인증을 완료해 주세요.`
6. 저장 결과 창을 닫거나 [취소]하면 다시 잠금(다음 변경 때 재인증).

### 15.4 주소(카카오 우편번호 서비스)
- 스크립트 `https://t1.kakaocdn.net/mapjsapi/bundle/postcode/prod/postcode.v2.js`(`kakao.Postcode`, 없으면 `daum.Postcode`). [우편번호 검색] → 전체 화면 레이어 `우편번호 검색`에 embed. `file://`로 열면 레이어 위 빨간 안내 `파일로 연 화면(file://)에서는 주소를 골라도 입력되지 않습니다. 프로젝트 폴더의 프로토타입 실행.bat으로 열어 주세요.`
- 선택(`oncomplete`): 도로명(R)이면 도로명 주소 + 참고항목(`동|로|가`로 끝나는 법정동, 아파트면 건물명)을 괄호로, 지번이면 지번 주소. 우편번호(`zonecode`)·기본 주소 채움, 상세 주소 비우고 포커스. 레이어는 ×·바깥 클릭·Esc로 닫힘.
- 우편번호·기본 주소는 직접 수정 불가(서비스 로드 실패 시에만 직접 입력 허용). [주소 지우기]는 값이 있을 때만 표시.

### 15.5 [저장하기] 처리
1. 다른 탭 탈퇴 확인 → 검사(이름·생년월일·닉네임·주소·관심분야 → 민감정보 → 비밀번호). 오류면 첫 `.invalid`(없으면 이름)로 포커스.
2. 바뀐 항목만 `fields`로 모으고 히스토리 문구 생성(비어 있으면 `미입력`):
   - `이름 변경: A → B` · `생년월일 변경: …` · `닉네임 변경: …` · `성별 변경: 미입력 → 여`
   - `이메일 변경: a@x.com → b@y.com (휴대폰 본인 인증)` + 이메일 로그인 계정이면 `로그인 아이디 변경: a@x.com → b@y.com (이메일 변경)`(결과 목록 라벨 `이메일 (로그인 아이디 포함)`)
   - `휴대폰 번호 변경: 010-1111-2222 → 010-3333-4444 (휴대폰 본인 인증)`
   - `주소 변경: 미입력 → (06236) 서울 강남구 테헤란로 152 12층` · `관심분야 변경: 여행 → 여행 · 반려동물(직접 입력)`
   - `마케팅 목적 개인정보 수집·이용 변경: 동의 → 거부` · `SMS 수신 변경: …` · `메일 수신 변경: …`(관리자 상세 문구와 동일)
3. 변경도 없고 새 비밀번호도 없으면 토스트 `변경된 내용이 없습니다.`
4. `MemberData.updateProfile(no, fields, logs, '회원')`(§17.5). 오류(`이미 가입된 휴대폰 번호입니다.` / `이미 사용 중인 이메일입니다.` / `회원 정보를 저장하지 못했습니다. 잠시 후 다시 시도해 주세요.`)는 폼 오류 박스. 탈퇴 계정이면 로그아웃.
5. 로그인 아이디가 바뀌었고 `stopbook.savedLoginId`가 예전 아이디면 새 아이디로 교체.
6. 새 비밀번호가 있으면 `Auth.setPassword(no, pw, { by:'회원', content:'패스워드 변경 (회원정보 수정)' })`.
7. 유틸 메뉴 이름 갱신 → 결과 창(§15.6).

### 15.6 저장 결과 창
- `회원정보가 수정되었습니다` + 목록 `· {항목} 변경`(이름/생년월일/이메일 (로그인 아이디 포함)/휴대폰 번호/닉네임/성별/주소/관심분야/마케팅 정보 수신 동의/비밀번호).
- 수신 동의를 바꾼 경우 `수신 동의 변경 결과` / `처리 일시: YYYY-MM-DD HH:mm · 전송자: 스탑북` / `마케팅 목적 개인정보 수집·이용: 동의|미동의` / `SMS 수신 동의|수신 거부 · 이메일 수신 동의|수신 거부`.
- [확인] → 저장값으로 폼 재채움(민감정보 잠금), 맨 위로.
- 관리자 반영: 회원 상세 기본 정보·가입 정보(수신 동의)·주소·관심분야에 새 값, 목록·검색·엑셀에도 반영, 히스토리 담당자 `회원`.

## 16. 회원 탈퇴 (PRD_MEM_010 · IA: 회원탈퇴)

### 16.1 진입
- 회원정보 수정 하단 [회원 탈퇴] → `#withdraw` → 비밀번호 확인(§14, 탈퇴 문구) → 탈퇴 화면. 서브 탭에는 없음.
- 설정 출처: 관리자 > 회원 유형 관리 > 탈퇴회원 > `자진탈퇴`(code `voluntary`) — 기본값 사유 선택 **필수** · **복수 선택** · 재가입 제한 **30일** · 사유 9개(가격이 비쌈 / 더 이상 이용하지 않음 / 편집기 사용이 어려움 / 제작·배송 기간이 김 / 인쇄 품질·색감 불만 / 원하는 상품·옵션 없음 / 상담·응대 불만 / 개인정보 보호 / 기타(의견 입력 받음)). 저장소를 읽지 못하면 선택·복수·제한 없음으로 동작.

### 16.2 화면 구성
1. **탈퇴 전 꼭 확인해 주세요**: `탈퇴하면 보유한 혜택이 모두 소멸되며, 다시 가입해도 복구되지 않습니다.` · 소멸 혜택 타일(마일리지 P · 쿠폰 장 · 상품권 원, `MemberData.withdrawCheck`) · 안내 목록(해당할 때만):
   - `마일리지·쿠폰·상품권은 탈퇴 즉시 소멸되며 복구할 수 없습니다.`
   - `장바구니에 담긴 상품 n종과 편집 중인 작업물이 삭제됩니다.` / 없으면 `장바구니와 편집 중인 작업물이 삭제됩니다.`
   - `답변을 기다리는 1:1 문의 n건의 답변을 받을 수 없습니다.`
   - `배송 중인 주문 n건은 그대로 배송되지만, 탈퇴 후에는 교환·반품을 마이페이지에서 신청할 수 없습니다. 고객센터(080-860-1119)로 문의해 주세요.`
   - 스탑북 `같은 아이디(이메일)로 다시 로그인할 수 없습니다.` / SNS `{SNS} 계정 연결이 해제되며, 같은 계정으로 다시 로그인할 수 없습니다.`
   - 막는 주문이 있으면 빨간 박스 `진행 중인 주문 N건이 있어 지금은 탈퇴할 수 없습니다.` + 최대 3건 `· {주문일} {상품} ({상태}[ · {결제상태}])` + `· 외 n건` + `주문을 취소하거나 결제를 마치고, 상품 배송이 시작된 뒤 다시 신청해 주세요.` → [탈퇴하기] 비활성.
2. **개인정보 처리 안내** 표: 즉시 파기 / 법령에 따라 보관(주문·결제·배송 5년, 불만·분쟁 3년, 분리 보관) / 재가입(`탈퇴 후 N일 동안은 같은 이메일·휴대폰 번호로 다시 가입할 수 없습니다. 다시 가입해도 이전 혜택·주문 내역은 이어지지 않습니다.` 또는 `탈퇴 후 바로 다시 가입할 수 있습니다. …`).
3. **탈퇴 사유** (설정별):

| 설정 | 화면 |
|---|---|
| 사유 있음 · required | 제목 `탈퇴 사유 필수`, 안내 `해당하는 사유를 모두 골라 주세요.`(복수) / `가장 큰 사유 하나를 골라 주세요.`(단일) + ` 서비스 개선에 참고하겠습니다.` |
| 사유 있음 · optional | 제목 `탈퇴 사유 선택`; 단일 선택이면 `선택 안 함` 라디오 추가 |
| auto 또는 사유 없음 | 사유 목록 숨김, 제목 `남기실 의견 선택`, 안내 `서비스 개선에 참고할 의견이 있다면 남겨 주세요.`; 저장 시 사용 중인 첫 사유 자동 기록 |
   - 복수 = 체크박스 / 단일 = 라디오. 의견 textarea 200자 + 카운터 `n / 200`, placeholder `서비스 개선에 참고할 의견을 남겨 주세요. (선택)` → 의견 입력 사유(기타) 선택 시 `기타 사유를 입력해 주세요. (필수)`.
4. **동의**: `안내 사항을 모두 확인했으며, 회원 탈퇴에 동의합니다.`
5. [취소](→ `mypage.html`) [탈퇴하기](빨간 버튼).

### 16.4 탈퇴 완료 화면
- `✓ 회원 탈퇴가 완료되었습니다` · `{탈퇴일}에 탈퇴 처리되었습니다. 그동안 스탑북을 이용해 주셔서 감사합니다.` / `개인정보는 모두 파기되었으며, 주문·결제 기록은 관련 법령에 따라 보관 후 파기됩니다.` / 제한 있으면 `**YYYY-MM-DD**부터 같은 이메일·휴대폰 번호로 다시 가입할 수 있습니다.` · [스탑북 홈으로]→`signup.html`.
- 이후: 같은 계정 로그인 불가(없는 계정과 같은 "맞지 않습니다"), SNS도 동일 계정 로그인 불가, 제한 기간 내 같은 이메일·휴대폰 재가입 차단(§6.3·§7.3).
- 관리자 반영: 통합 회원 관리에 '탈퇴' 상태로 남음(이름 `탈퇴회원`, 아이디·이메일 앞 2자 마스킹, 휴대폰 `파기됨`, 혜택 0 + 내역 `회원 탈퇴로 소멸`), 탈퇴 회원 관리 목록·분석에 추가(스냅샷), 히스토리 `회원 탈퇴 (자진탈퇴 · 사유: … · 의견: …)` + `개인정보 파기 … · 보유 혜택 소멸 (마일리지 nP · 쿠폰 n장 · 상품권 n원)`, 대기 중 단체 신청 자동 취소, 다른 화면 저장 사본의 개인정보 치환.

| `login(id, pw, env)` | 회원 없음·SNS 회원(비밀번호 없음)·불일치 모두 `{error:'mismatch'}`; 잠금 중 `{error:'locked', until}`; 실패 5회째 잠금 설정 + 히스토리 `로그인 5회 연속 실패로 10분간 로그인 제한`; 성공 시 fail 0, `recordLogin`, 반환 `{ member, change:'temp'|'expired'|'', changedAt }`. 스탑북 샘플 회원은 저장값이 없으면 샘플 비밀번호(변경일 = 가입일), 쇼핑몰 가입 회원은 저장값 없으면 '미설정' |
| `verifyPassword(no, pw)` | 마이페이지 게이트. `{ok}` / `{error:'mismatch', fails, remain}` / `locked` / `unset`. 실패 횟수를 로그인과 공유 |
| `setPassword(no, pw, {temp, by, log, content})` | 해시·변경일시 갱신, temp·fail·잠금·snooze 초기화, 히스토리(기본 `패스워드 변경`, 담당자 기본 관리자) |
| `isSamePassword` · `snoozePassword` · `recordLogin` · `unlockLogin`(관리자) · `authInfo`(관리자 표시) | |
- 매번 저장소를 다시 읽어(`authOf`) 다른 탭에서 바꾼 값을 되돌리지 않고, 탈퇴 회원 값은 저장하지 않음.

### 17.2 중복·재가입
- `findDuplicate({email, phone}, exceptNo)`: 탈퇴하지 않은 회원 중 휴대폰(숫자만) 우선 → 이메일(소문자). 반환 `{ field, member }`.
- `rejoinBlock({email, phone})`: `stopbook.memberWithdrawals.v1`의 기록 중 `rejoinUntil`이 오늘 이후이고 `phoneHash`/`emailHash`(cyrb53, 원문 복원 불가)가 같으면 `{ until, field }`.

### 17.3 가입 `registerMember(rec)`
- 중복 → 재가입 제한 → 다른 탭에서 방금 가입한 기록(`stopbook.signupMembers.v1`에 있으나 이 화면 메모리에 없는 것)과도 비교 → `no` = 메모리·저장소 최대+1, 등급 `일반`, 가입일·최근접속일 오늘, 히스토리 `회원 가입 ({가입유형})`(담당자 회원) + 전달한 history → 저장 후 `attachSignup`으로 즉시 회원 목록에 합류(구분 일반, 주문·문의·장바구니 없음, ledger 재계산).

### 17.4 SNS 식별
- `snsKey(code, email)` = `{code}:{email 소문자}` — 가입 시 저장(`stopbook.signupMembers.v1`의 `snsKey`). `findSnsMember(code, email, typeName)`: snsKey 일치 → 없으면 snsKey 없는 회원 중 같은 가입유형·이메일. TODO: OAuth `sub`로 대체.

### 17.5 회원정보 수정 `updateProfile(no, fields, contents, by)`
- 저장 `stopbook.memberProfile.v1` = `{ [no]: { fields, log[] } }`. 허용 필드: name·email·userId·phone·birth·nickname·gender·zipcode·address1·address2·interests·interestEtc·marketingUse·marketingSms·marketingEmail·snsKey. 저장 전 중복 재확인(본인 제외), 탈퇴 회원 거부(`{error, withdrawn:true}`). SNS 회원이 이메일을 바꾸면 바꾸기 전 이메일로 `snsKey`를 남겨 다음 SNS 로그인에서 같은 회원을 찾음. 페이지 로드 시 회원 데이터에 덮어쓰고 로그를 히스토리에 합침.

### 17.6 탈퇴 `withdrawCheck(m)` · `withdraw(no, opts)`
- 막는 주문: 제작상태 `주문대기·주문완료·제작중` 또는 결제상태 `입금대기·후결제대기·부분결제`. 관리자 취소(`stopbook.orderCancels.v1`)·입금(`stopbook.orderDeposits.v2`) 처리 반영. 배송 중 주문은 안내만.

### 21.2 1:1 문의 접수 (`#iqForm`)
- 고객 정보(이름·연락처·이메일)는 **화면에 표시하지 않음** — 로그인 회원 정보로 접수하고 답변 알림도 회원 정보의 연락처·이메일로 보냄.

| 순서 | 항목 | 규칙 | 오류 문구 |
|---|---|---|---|
| 1 | 문의 유형* | 칩 단일 선택 | 문의 유형을 선택해 주세요. |
| 2 | 제목* | 100자, 카운터 `n / 100` | 문의 제목을 입력해 주세요. / 제목은 100자 이내로 입력해 주세요. |
| 3 | 내용* | 서식 편집기(contentEditable). 툴바 **B · I · U · 글머리 목록 · 번호 목록 · 링크(http/https만) · Tx(서식 지우기)** + 오른쪽 **📎 첨부파일** 아이콘. 붙여넣기는 텍스트만. 카운터 `n / 5,000`(텍스트 길이) | 문의 내용을 입력해 주세요. / 문의 내용은 5,000자 이내로 입력해 주세요. |
| 4 | 첨부파일 | 툴바 📎로 선택 → 편집기 아래 목록(이름·크기·×). 이미지·PDF·문서(jpg, jpeg, png, gif, webp, pdf, hwp, hwpx, doc, docx, xls, xlsx, ppt, pptx, txt, zip), 파일당 10MB, 최대 5개, 같은 이름 중복 불가. 프로토타입은 파일명만 저장 | 제휴문의 첨부와 같은 문구 |
| 5 | 주문 상품(선택) | **문의 내용 아래. 모든 문의 유형에서 선택 입력**(필수 아님, 고르지 않아도 접수). 안내 "주문 관련 문의라면 해당 상품을 선택해 주세요. 주문번호를 누르면 상품이 펼쳐지며, 최대 20개까지 고를 수 있습니다." 직접 입력 없음 — 아래 주문 상품 선택 패널에서만 고름. 최대 20개 | 주문 상품은 20개까지 선택할 수 있습니다. / 최근 3개월 주문 상품만 선택할 수 있습니다. 목록에서 다시 선택해 주세요. |

- **주문 상품 선택 패널(`#iqPicker`)** — 주문이 100건 이상이어도 쓸 수 있게 구성:
  - 대상: 로그인 회원의 **최근 3개월** 주문(취소 상품 포함, 진행상태 "취소"). 주문일 최신순.
  - **주문번호 아코디언**: 처음에는 모두 접힘. 줄 = **주문번호** · "주문일 · 대표 상품명[ 외 n종]" · 고른 개수 배지("n개 선택", 접혀 있어도 표시) · ▾. 누르면 펼쳐져(`aria-expanded`, 펼친 줄은 스크롤 시 고정) 상품 행 = 체크박스 · 카테고리 약어 썸네일 · **상품명** · "카테고리 · n부 · 진행상태". 상품이 2개 이상인 주문은 맨 위에 "주문 전체 선택"(일부 선택 시 중간 상태). 펼친 상태는 페이지 이동 후에도 유지.
  - 선택 바: "선택한 상품 n/20" + 상품 칩(상품명 · 주문번호 뒷자리, × 제거) + [선택 해제]. 20개가 차면 체크 안 된 상품은 비활성 + 안내.
  - 도구: 기간 1개월/2개월/3개월(기본 3개월) · 진행상태(전체 상태 + 목록에 있는 상태) · 검색(상품명·주문번호, 입력 0.25초 뒤 자동, Enter 즉시). 검색·상태 필터 중에는 맞는 상품이 있는 주문만, 그 상품만 보이고 결과 주문은 자동으로 펼침. 검색·필터를 모두 지우면 다시 접음.
  - 목록: "최근 3개월 주문 N건 · 상품 M개 · p/P쪽", 높이 고정 스크롤(최대 420px). 페이지: **주문 10건씩**, 번호 페이지 이동(‹ 1 … 4 5 6 … 14 ›). 선택은 검색·필터·페이지를 바꿔도 유지. 데이터 `UserInquiry.searchOrders`.
  - 빈 상태: 최근 3개월 주문 없음 "최근 3개월 동안 주문한 상품이 없습니다. 주문 상품을 선택하지 않고 그대로 접수하시면 됩니다. 3개월이 지난 주문은 내용에 주문번호를 적어 주세요." / 검색 결과 없음 "검색 결과가 없습니다."
  - 모바일(≤480px): 기간 버튼 전체 너비, 진행상태·검색 아래로 쌓임.
- 하단 안내: "접수된 문의는 담당자가 확인한 후 순차적으로 답변드립니다. 답변이 등록되면 회원 정보의 연락처·이메일로 알림을 보내 드립니다." + 고객행복센터 080-860-1119 · 운영시간. 버튼 [다시 쓰기](작성 중이면 확인) [문의 접수].
- 검사: 화면 순서(유형 → 제목 → 내용 → 첨부 → 주문 상품)대로 모든 오류 표시 후 첫 오류로 이동(주문 상품은 선택이라 20개 초과·기간 밖 상품만 오류, 패널 검색창으로 이동) → `UserInquiry.submit`(같은 검사 + 본문 HTML 정리: b·i·u·ul·ol·li·a·br·p만 남김). 작성 중(유형·선택 상품·제목·내용·첨부) 다른 탭/화면 이동 시 `작성 중인 문의가 있습니다. 이동하시겠습니까?`(제휴문의와 공통), Esc = 작성 내용 지우기 확인(검색창 안 Esc 제외).
- 접수 완료(`#viewInqDone`): 접수번호 **Q{YYYYMMDD}-{번호}**, "담당자가 확인 후 순차적으로 답변드립니다. 답변이 등록되면 회원 정보의 연락처·이메일로 알림을 보내 드립니다.", 요약(유형 · 제목 · 주문 상품 최대 3개 + "외 n개" · 첨부 n개), [FAQ 보기] [문의 내역 보기]. 접수 확인 SMS는 관리자 > 메시지 발송 내역에 기록(가상).
- 저장 레코드: `{ no, memberNo, type, title, content, contentHtml, orderItems[{ orderNo, idx, name, category, qty }], files[], at, status '답변대기', user: true }`.

### 23.1 주문상태 — 관리자 값 → 고객 화면 상태 (IA 일반주문상태값: 유저페이지·관리자 상태값 통일)
`orderState(o)`(주문) · `itemState(o, it, i)`(상품 행) — 위에서부터 먼저 맞는 것.

| 관리자 값 (결제상태 · 제작상태 · 클레임 신청) | 고객 화면 상태 | 뱃지 톤 |
|---|---|---|
| 결제상태 `전체취소` (상품 행: 상품 결제상태 `취소`) | 환불완료 | 회색 |
| 취소 요청 승인 대기 (결제상태 `취소요청` 포함, 상품 행은 요청에 든 상품만) | 취소처리중 | 빨강 |
| 교환 신청 승인 대기 / 승인(재제작 진행) | 교환처리중 | 빨강 |
| 교환 승인 + `재출고 완료` | 교환완료 | 회색 |
| 반품 신청 승인 대기 | 반품처리중 | 빨강 |
| 반품 승인 (회수·환불) | 환불완료 | 회색 |
| 결제상태 `입금대기` (무통장입금 입금 전) | 입금대기 | 테라코타 |
| 제작상태 `주문완료` + 후결제 입금 전(`후결제대기`·`부분결제`) | 주문완료 (+`후결제`) | 테라코타 |
| 제작상태 `주문완료` + `결제완료`·`부분취소` | 결제완료 | 브랜드 |
| 제작상태 `제작중` | 제작중 (후결제면 +`후결제`) | 노랑 |
| 제작상태 `배송중(부분)`·`배송중(전체)`·`배송완료` | 발송완료 (후결제면 +`후결제`) | 초록 |

- 반려된 신청은 상태에 넣지 않음(신청 내역에 반려 사유). 여러 신청 중에는 가장 최근의 반려 아닌 교환·반품 신청 기준.
- `배송중(부분)`: 취소되지 않은 상품 중 출고된 상품이 있으면 발송완료, 출고 상품이 모두 취소됐으면 제작중.
- 보조 표기(테두리 뱃지): `후결제`(IA: 후결제는 주문완료·제작중·발송완료에 별도 표기) · `일부 취소`(결제상태 부분취소) · `일부 발송`(발송완료인데 아직 출고 안 된 상품이 있음).
- 결제상태 표기: 입금대기 / `결제대기 (후결제)` / `부분결제 (후결제)` / 결제완료 / `결제완료 (일부 취소)` / 결제취소 / 취소요청이면 `{원래 결제상태} · 취소 요청 중`.

### 23.3 주문 상세 (`#orders?no=주문번호`, IA R37)
- [‹ 주문 목록](목록 조건 유지) 아래 카드 6개:

  2. 상품 정보: 상품 행 + 옵션(사이즈(cm, 관리자 주문 데이터와 같은 값)·형태·커버·코팅·페이지 `24p(+6p)`·후가공) + [편집본 미리보기] + [편집본 공유](포토북·캘린더, 준비 중)
  3. 결제 · 할인 · 혜택 (`OrderData` `payment` 그대로 — 관리자 주문 상세 결제정보와 같은 숫자)
     - 결제 정보: 총 상품정가(`listPrice`, 페이지 추가·후가공이 있으면 `옵션 추가금액 포함`) · 배송비(`shipFee`, 도서산간 포함 표시) · 총 할인(`discount`) + 항목별(쿠폰·마일리지·상품가할인·배송비할인·회원할인·등급할인 중 0이 아닌 것) · 추가결제(`extraPay`) · 취소·환불(`cancel`) · **결제(예정)금액**(`total`)
     - 결제 수단·혜택: 결제상태 · 결제수단 · 결제일시(`paidDateTime`, 없으면 `결제 전`) · 결제 시 증빙 요청(`docType(docPurpose) · docStatus`) · 사용 마일리지(할인 > 마일리지 = 회원 마일리지 내역의 '주문 결제 시 사용') · 적립 마일리지(`point`, 결제 전이면 `결제 완료 후 적립`) · 총 혜택금액(할인 + 적립)
  4. 배송 정보: 배송상태(+[배송조회]) · 택배사/퀵 업체 · 운송장. 배송지 목록(`delivery.addresses`: 기본 배송지 + 관리자가 나눈 추가 배송지, 여러 건이면 배송 상품 표시) — 수령인(없으면 `입력대기`)·연락처·배송주소·배송메모. 기본 배송지에만 [배송지 변경](입금 전). 입금·결제 뒤에는 `배송지는 입금(결제) 전까지만 바꿀 수 있습니다. 고객센터(080-860-1119)로 문의해 주세요.`, 추가 배송지가 있으면 `나누어 보내는 추가 배송지는 고객센터에서 바꿀 수 있습니다.` 방문수령은 수령 장소.
  5. 취소 · 교환 · 반품 신청 내역(IA에 없음, 추가): `ClaimData.requestsOf` 최근 순 — 유형(`취소 요청(전체|부분)`·`교환 신청`·`반품 신청`) · 상태(승인 대기/처리 완료/반려) · 신청번호 · 일시 · 상품 · 사유(상세) · 환불 수단 · 처리 결과(교환: 재제작 진행/재출고 완료, 취소·반품: 환불 금액·수단·처리일시) · 반려 사유. 없으면 `취소·교환·반품 신청 내역이 없습니다.`
  6. 증빙서류 신청 · 발급 내역(IA에 없음, 추가): 발급 신청(`DocData.requests`, 처리 대기/발급 완료/반려 + 수령 방법·희망일·반려 사유) + 발급 이력(`DocData.issues`, 결제 확인 자동 발급·주문서 견적서 등 포함, 바로 발급 서류는 [다시 받기] — 발급 이력은 늘지 않음). 제목 옆 [증빙서류 발급].

### 23.4 주문 취소 · 부분취소 (모달 `#odDlg`, 관리자 클레임관리 > 취소 요청 관리로 접수)
- [주문취소]: 취소 가능 상품 모두 선택된 채로 열리고, 일부만 취소하려면 체크를 풀면 됨(부분 취소). 취소할 수 없는 상품은 비활성 + 이유(`이미 취소된 상품입니다.` · `출고된 상품은 취소할 수 없습니다. 받은 뒤 교환/반품을 신청해 주세요.` · `제작이 시작되어 취소할 수 없습니다.`).
- 취소 사유(필수, `ClaimData.CANCEL_REASONS`: 단순변심·주문 정보 오류·중복 주문·제작·배송 지연·기타) · 상세 사유(선택, '기타'면 필수, 500자).
- 환불 수단(`ClaimData.refundKindOf`): 결제 전(입금대기·후결제대기) `결제 전 주문이라 환불할 금액이 없습니다.` / 현금성 결제(무통장입금·계좌이체·후결제·별도결제) 환불 계좌 — 은행(`REFUND_BANKS`)·계좌번호(숫자 10~16자리)·예금주(기본 회원 이름) / 그 외 `원결제수단 취소 ({결제수단})`.
- `환불 예정 금액` = 고른 상품 결제금액 합계(결제 전은 `0원 (결제 전)`) + `배송비·할인(쿠폰·마일리지)이 반영된 최종 환불 금액은 담당자 확인 후 정해집니다.`
- [취소 요청] → 확인 창 `선택한 상품 n건의 취소를 요청할까요?…` → `ClaimData.submitCancel` → 토스트 `취소 요청이 접수되었습니다. (신청번호 C…)` → 화면 다시 그림(상태 취소처리중).
- 오류 문구(버튼 위 + 칸 표시): `취소할 상품을 선택해 주세요.` · `취소 사유를 선택해 주세요.` · `기타 사유를 입력해 주세요.` · `환불받을 은행을 선택해 주세요.` · `환불 계좌번호를 정확히 입력해 주세요. (숫자 10~16자리)` · `예금주를 입력해 주세요.` · `이 주문은 이미 취소 요청이 접수되어 처리 중입니다.` · `제작이 시작되었거나 이미 취소된 상품은 취소할 수 없습니다: …`

### 23.5 배송지 변경 (IA R38)
- 현재 배송지 요약 + 수령인(필수, 한글·영문 2~20자) · 연락처(필수, 자동 하이픈, 휴대폰·일반전화) · 배송주소(필수, [우편번호 검색] = 회원정보 수정과 같은 카카오 우편번호 레이어를 모달 안에 띄움, 못 불러오면 직접 입력) · 상세 주소(필수) · 배송메모(선택 50자) · `회원정보 주소로도 저장`(IA '신규 배송지로 등록' 대신 — 배송지 목록 기능 없음).
- 안내: `배송지를 바꿔 지역별 배송비(도서산간 추가 배송비 등)에 차액이 생기면 고객센터(080-860-1119)에서 따로 안내해 드립니다. 상품이 출고된 뒤에는 배송지를 바꿀 수 없습니다.`(IA: 현재 차액은 수동 처리)
- [변경 요청] → `OrderData.saveAddress(주문번호, 'base', {recipient, phone, zip, address, detail, request})`(localStorage `stopbook.orderAddresses.v1`) + 주문 히스토리 `OrderData.addHistory(주문번호, '배송지', '고객 배송지 변경 (마이페이지): 수취인명 A → B, …', '고객')` → 토스트 `배송지가 변경되었습니다.` 바뀐 게 없으면 `변경된 내용이 없습니다.` 회원정보 주소 저장을 고르면 `MemberData.updateProfile`(회원 히스토리 `주소 변경: … (주문 … 배송지 변경에서 저장)`).
- 오류: `수령인 이름을 한글 또는 영문 2~20자로 입력해 주세요.` · `연락처를 정확히 입력해 주세요.` · `우편번호 검색으로 배송주소를 입력해 주세요.` · `우편번호 5자리를 확인해 주세요.` · `상세 주소를 입력해 주세요.`
- Esc는 우편번호 레이어가 열려 있으면 레이어만 닫음.

### 23.6 배송조회 (IA R39)
- 단계 3칸(출고 전 · 배송중 · 배송완료, 시각) · 배송방법 · 택배사(퀵 업체)/수령 장소 · 운송장번호 · 배송상태 · 집하 · 배송완료 · 상품별 표(상품·수량 · 제작번호 · 고객 상태 + 출고 시각, 상품 행에서 열면 그 상품 강조).
- 운송장이 없는 택배 주문: `출고 전입니다. 상품이 출고되면 운송장번호를 알려 드립니다.`
- 운송장이 있으면 [{택배사}에서 배송조회 ↗] = `delivery.trackingUrl`(새 창, 관리자 주문 상세와 같은 주소).

### 23.7 증빙서류 발급 (IA R43)
- **바로 발급**(`DocData.INSTANT_TYPES`): 견적서 · 거래명세서(데이터 `거래내역서`, 결제 확인 후) · 사업자등록증 · 통장사본(무통장입금=가상계좌 주문은 비활성, `DocData.BANK_COPY_BLOCK_REASON`) · 카드영수증(카드·간편결제 결제 완료 주문, 준비 중). 누르면 `DocData.issueByCustomer` → 발급 이력(발급번호 `C{YYYYMMDD}-NNNN`, 경로 `마이페이지`, 처리 고객) + 주문 히스토리 `서류발급 … 마이페이지 바로 발급` → 관리자와 같은 양식(`DocForms.build`, 견적서·거래명세서는 주문 상품·금액, 사업자등록증·통장사본은 스캔본)을 `{양식}_{주문번호}.html`로 내려받음 + 토스트.
- **발급 신청**(`DocData.CUSTOMER_REQUEST_TYPES`, 칩 여러 개): 세금계산서 · 현금영수증(둘 다 현금성 결제 주문만, 아니면 비활성 + 안내) · 납품서 · 견적서(기관 양식·직인) · 거래명세서(기관 양식·직인) · 기타. 결제 때 요청한 증빙이 있으면 `결제할 때 요청한 {종류}은(는) {발급상태} 상태입니다.`
  - 입력: 담당자명·연락처·이메일(필수, 사업자 회원은 담당자 정보로 채움) · 기관/회사명 · 세금계산서 → 사업자등록증 파일(필수, 파일명만, 영수/청구 자동) · 현금영수증 → 소득공제(휴대폰)/지출증빙(사업자등록번호 10자리) · 받는 방법 이메일/팩스/우편 + 받을 곳 · 발급 희망일(필수, 기본 오늘+3일, 오늘 이후) · 요청 사항(기타·납품서면 필수, 500자) + 양식 파일(선택, 파일명만).
  - [발급 신청] → `DocData.submitRequest` → 관리자 등록과 같은 방식으로 증빙서류(D…)·영수증(R…) 접수로 나눠 처리 대기 → 토스트 `서류 발급 신청이 접수되었습니다. (신청번호 …)`.
  - 오류: `발급 신청할 서류를 선택해 주세요. 표준 양식은 위의 바로 발급에서 내려받을 수 있습니다.` · `세금계산서를 신청하려면 사업자등록증 파일을 첨부해 주세요.` · `현금영수증 발급용 휴대폰 번호를 정확히 입력해 주세요.` · `사업자등록번호 10자리를 정확히 입력해 주세요.` · `받을 이메일 주소를 정확히 입력해 주세요.` · `이미 접수되어 처리 중인 서류가 있습니다: …` · `발급 희망일을 오늘 이후 날짜로 선택해 주세요.` · `요청 사항에 필요한 서류와 양식을 적어 주세요.`

### 23.8 교환/반품 신청 (모달, 관리자 클레임관리 > 교환 반품 관리로 접수)
- 안내: 맞춤 제작 상품이라 단순 변심 교환·반품 불가, 교환 = 같은 사양 재제작(무상), 반품 = 회수 후 환불.
- 신청 구분 교환(재제작)/반품(환불) · 상품(배송완료 상품만 선택 가능, 하나면 미리 선택) · 불량 유형(필수, `ClaimData.DEFECTS`) · 불량 내용(필수 10~500자) · 사진(선택, 이미지 jpg·jpeg·png·gif·webp·heic, 장당 10MB, 최대 5장, 파일명만 저장 — 1:1 문의 첨부 규칙과 같은 개수) · 반품이면 환불 수단(23.4와 같음).
- [신청하기] → `ClaimData.submitExchange` → 토스트 `{교환|반품} 신청이 접수되었습니다. (신청번호 X…)` → 상태 교환처리중/반품처리중.
- 오류: `{유형}할 상품을 선택해 주세요.` · `불량 유형을 선택해 주세요.` · `불량 내용을 10자 이상 적어 주세요.` · `사진은 최대 5장까지 첨부할 수 있습니다.` · `사진 파일(…)만 첨부할 수 있습니다: …` · `이 주문은 이미 교환·반품 신청이 접수되어 처리 중입니다.` · `배송이 완료된 상품만 {유형} 신청할 수 있습니다: …`

### 25.2a 이벤트 할인가 (샘플, 2026-10-27)
- 장바구니의 상품 1건에는 늘 이벤트 할인이 적용된 상태로 보여 줌(샘플 `가을 포토북 기획전` 20%, 2026-11-30까지). 이벤트가 붙은 항목이 없으면 주문 가능한 첫 편집 상품(없으면 첫 항목)에 화면에서만 붙임 — 그 항목을 삭제하면 다음 항목으로 옮겨감. TODO: 이벤트·기획전 관리의 적용 상품·할인율로 서버 계산.
- 할인가 = 기본가 × (1 − 할인율), 10원 단위 내림. 기본가(`price`)는 그대로 두고 표시·합계만 할인가.
